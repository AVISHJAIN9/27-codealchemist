# 14.9 Reliability, Fault Tolerance & Resilience Engineering

## 1. What It Is in Plain Words
Reliability engineering ensures a system continues operating correctly even when infrastructure, networks, or upstream third-party dependencies fail. Resilience patterns prevent isolated errors from cascading into catastrophic system-wide outages.

## 2. Resilience Patterns Implemented in TruthGuard

    Request[User Request] --> Breaker{Circuit Breaker State}

### 1. Circuit Breaker Pattern
* **Problem**: If an upstream AI inference provider experiences an outage, requests hang for 15 seconds before timing out, tying up browser worker threads and gateway connections.
* **Mitigation**: A circuit breaker trips after 5 consecutive failures within a 10-second window. Once tripped, subsequent requests bypass the upstream API immediately, returning deterministic heuristic fallback verdicts while periodically testing health via a half-open state.

### 2. Retries with Exponential Backoff & Full Jitter
* **Formula**:
  $$t_{\text{wait}} = \min(t_{\text{max}}, t_{\text{base}} \times 2^{\text{attempt}}) \times \text{random}(0, 1)$$
* Prevents the "thundering herd" effect where hundreds of failed requests retry at the identical millisecond interval.

## 3. Availability Targets: SLI, SLO & SLA

* **Service Level Indicator (SLI)**: Percentage of successful forensic API invocations completed with latency < 2.0 seconds.
* **Service Level Objective (SLO)**: 99.9% of valid requests return within 2.0s over any rolling 30-day window.
* **Service Level Agreement (SLA)**: 99.5% monthly availability, backed by financial service credits.
* **Disaster Recovery**:
  - **Recovery Point Objective (RPO)**: < 5 minutes (via automated WAL archiving in PostgreSQL).
  - **Recovery Time Objective (RTO)**: < 15 minutes (via multi-region automated database failover).
